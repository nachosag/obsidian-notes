# <mark style="background: #FFB8EBA6;">Límites O Limitaciones</mark>

Un límite o límite técnico se refiere a cualquier restricción que es impuesta por la **tecnología, el entorno o la implementación específica**, en lugar de ser una regla inherente al negocio mismo.

- **No viene del negocio:** Una regla de negocio (dominio) existiría aunque hicieras el sistema con papel y lápiz. Un límite técnico, en cambio, solo aparece porque estás usando una computadora, una web, una base de datos o un framework determinado.
- **El ejemplo del mensaje de error:**
	
    - El autor explica que decidir el **color rojo** para un error o preocuparse por el **"Content Layout Shift"** (evitar que la web salte visualmente) son límites técnicos.
    - Esto es así porque la **UX (experiencia de usuario)** y la estabilidad de la interfaz web te imponen restricciones técnicas que debes resolver. Si el sistema fuera una terminal de texto antigua o una app de voz, esos "límites" no existirían o serían completamente diferentes.
	
- **El "cómo" vs. el "qué":** El límite técnico es la frontera donde el mundo abstracto de la lógica de negocio choca con la realidad del desarrollo. Mientras que la regla de negocio define *qué* debe pasar (ej. "el usuario debe ser mayor de 18"), el límite técnico define *cómo* vas a implementar esa respuesta dentro de la arquitectura de tu aplicación para que sea funcional, performante y accesible.
